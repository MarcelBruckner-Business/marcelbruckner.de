Auditing a self-hosted finance app before it meets my bank

I wanted one place that shows all my money: current accounts, savings, depots, loans. I did not want that place to be someone else’s cloud. So I set up Securo, an open-source finance manager, on my own server, and before I let it near a bank account I had Claude read its code with me. This is what came out of that day, in the order it happened.

Reading the code first

Securo is eight months old, mostly written by one person, and ships a release every few days. That is no reason to avoid it, but it is a reason to look.

We read the parts that decide who gets in and what they can see: sign-in, API tokens, how data is separated between workspaces, the bank connection, file storage, and every endpoint that works without a login. Both dependency lockfiles went through the OSV vulnerability database. Then we probed my running instance from outside.

What held up:

  • 26 of 329 API operations work without a login, and with local passwords switched off the sensitive ones answer 403.
  • Single sign-on is done properly (PKCE, nonce, issuer and audience checked).
  • No raw SQL, no path tricks in file storage, API tokens are hashed and scoped.
  • No telemetry. The server only talks to the providers you configure.

What did not:

  • The session token lives in the browser’s localStorage, is valid for 24 hours, and logging out does not revoke it.
  • The app sends no security headers.
  • The bank connection’s credentials sit unencrypted in the database, next to a code comment that says “Encrypted tokens”.
  • The interactive API documentation is public.

None of that is a hole by itself. Together it means one injected script would be enough to take over a session.

A policy the app does not send

The fix did not need a change to Securo. My reverse proxy (Caddy) now adds a Content-Security-Policy in front of it: scripts only from the site itself, requests only to the site and to GitHub’s release check. An injected script can no longer run, and could not send the token anywhere if it did.

You can write such a policy without clicking through the app. Fetch the built index.html; if it has no inline script, script-src 'self' works. Then grep the frontend source for what it loads from elsewhere (fonts, logos, blob: previews, a PDF worker) and allow exactly that. The proxy also answers 404 for the API documentation.

What “connect your bank” really gives you

Securo talks to European banks through Enable Banking, a Finnish provider that is licensed only to read account information. That limit is the good news: whatever goes wrong, nobody can move money through it. For your own accounts it is free.

Three things I did not expect:

  1. You approve twice. First you link your accounts in Enable Banking’s control panel, which only puts them on your application’s allow-list. Then the app asks for its own consent, and the bank has you approve again.
  2. You get 90 days of history, not years.
  3. You get current accounts and nothing else. The law behind this interface (PSD2) covers payment accounts. Savings accounts, depots and loans are not offered through it, whichever aggregator you pick. One of my banks delivers transactions with amount and date only, no text at all.

The part that takes weeks

For savings accounts and depots, German banks have their own older protocol, FinTS. It logs in as you, with your online-banking PIN, which is a very different kind of trust than a read-only consent. And every program that speaks it, a private script included, needs a registration number from the banking association: a PDF form, sent by e-mail, answered in “two weeks or longer”.

What I would tell someone starting today

  • Read the code of anything that gets your bank data, or have it read. It took an afternoon.
  • Put the security headers in your proxy if the app does not send them.
  • Decide what you want to see before you connect anything. I imported a year of CSV first, then connected the bank, and had the last 90 days twice.
  • Expect “bank sync” to mean current accounts. Everything else is still work.
