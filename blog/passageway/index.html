passageway: Claude finds the right passage in your sources

The idea

Claude should find the right few passages in what you have written down, give you the links, and say nothing when nothing fits. passageway does that as a small server with one MCP tool, recall. It is the retrieval half of a RAG system. It never writes the answer itself: the model that calls it reads the passages and does that.

Why it exists

It grew out of trilium-recall, which does this for Trilium notes. The part worth keeping was never Trilium: it was the search, the relevance gate that keeps weak matches out of the prompt, and the habit of measuring. passageway pulls that out into a core that knows no source at all.

How it works

  • A connector is any program that lists items and prints their text as JSON Lines. It can be written in any language, and passageway ships a contract check that tells you whether yours is right.
  • The core indexes what connectors report, with keyword and embedding search in one SQLite file per source, on the CPU.
  • A relevance gate lets it return nothing instead of padding a prompt with a weak match.
  • Authentication is a bearer password, or an OAuth login page for remote clients.

What exists today (v0.1.0)

  • The core and the connector protocol
  • A Wikipedia connector that indexes a topic, some articles or a place, in English and German
  • A documentation site with a guide to writing your own connector
  • A release workflow that produced this feed: every tagged release posts its notes here

What comes next

A markdown connector and a frozen Wikipedia corpus, then an evaluation harness that measures retrieval quality on your own questions and builds a report you can publish. After that: a choice of embedding models, a container image, a Claude Code plugin for the prompt hook, and connectors for Trilium and Confluence.
