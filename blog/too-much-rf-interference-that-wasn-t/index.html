"Too much RF interference" that wasn't

I updated the firmware of our Zigbee coordinator (an SMLIGHT SLZB-06P7) this morning, after taking a ZHA backup. Afterwards Home Assistant could not bring the network back. Every restore failed with:

zigpy.exceptions.FormationFailure: Network formation refused: there is too much RF interference. Make sure your coordinator is on a USB 2.0 extension cable and away from any sources of interference, like USB 3.0 ports, SSDs, 2.4GHz routers, motherboards, etc.

So I went hunting for interference. Three more firmware builds, power cycles, an energy scan. Nothing changed, and our flat had no Zigbee for 77 minutes.

What actually happened

The message was wrong about the cause.

  1. Flashing the radio erases the network it holds. PAN ID, network key, frame counters: gone. Only the backup in Home Assistant still has them.
  2. Restoring the backup is a network formation. Before the flash the radio just resumed its stored network; now it has to form it again, and before forming it scans the channel.
  3. The scan finds the network already running. Every Zigbee plug and lamp in the flat is a router, and they all kept the old network alive during the flash. The radio sees its own PAN ID on the air, refuses to form it, and zigpy-znp reports the timeout as “too much RF interference”.

The fix: ten seconds with a screwdriver

Unscrew the coordinator’s antenna so it cannot hear the routers, run the restore, screw the antenna back on. The network came back, and not a single device had to be re-paired. The next firmware update, done that way from the start, restored itself in 90 seconds.

If you flash a Zigbee coordinator

  • Take a backup first.
  • Make the coordinator deaf to your routers (antenna off, or switch off the routers near it).
  • Flash, restore, then reconnect the antenna.
  • If you see “too much RF interference” right after a flash, think “my own network is still on the air” before you think “interference”.

SMLIGHT’s manual actually says it: the same message appears when a network with the same PAN ID already exists. I found that page an hour too late.
