notefeed 0.31.0: share pictures from the phone, images cleaned on the server

notefeed 0.31.0 is out.

  • You can share pictures to notefeed from your phone. On Android, notefeed installed from Chrome now shows up in the share sheet for pictures, text and links. Pick a feed and they wait in its compose box until you post. Samsung Internet’s installed app does not do this yet. On the iPhone, a Shortcut does the same, and the new docs page “Sharing from a phone” shows how to set it up. Pictures in one post may now share a file name, unless the text refers to that name.
  • Every image is now shrunk to at most 2560 px, turned upright and stripped of its location and camera data on the server, whatever posted it. Animations stay. An upload may now be up to 10 MiB instead of 5, so a phone photo can go as it is.
  • A title image uploaded in a feed’s settings belongs to the feed and no longer shows up as a post. Scripts can set it with PUT / DELETE /api/v1/feeds/{feed}/image, setFeedImage / removeFeedImage (JS) or set_feed_image / remove_feed_image (Python). Title images uploaded before stay posts until you set them again. The footer and the ⓘ menu show the version an instance runs. On a wide screen, a note’s page has a large “All notes” link beside it, and large pictures in notes are kept to a sensible size. A new page linked from the footer, “Values”, says what notefeed stands for.
  • AI assistants can now set a feed’s title image with set_feed_image, and pictures posted with post_note may share a name unless the markdown refers to it. Assistants see the new tool only after reconnecting. In Claude, start a new chat, or remove and add the notefeed connector if it still does not show. In Claude Code, restart it.
  • Breaking: a file that only starts like an image but is not one is now refused with 415, and an image over 100 megapixels with 413. When the server is busy with images it answers 503 with Retry-After, which both clients raise as RateLimitedError. Wait the given time and try again.
  • If you run notefeed yourself, remove NOTEFEED_SHRINK_IMAGE_BYTES: it is no longer used and logs a warning at startup. NOTEFEED_MAX_IMAGE_BYTES now defaults to 10 MiB, which is also the most it can be set to.

All the details are in the release notes and on GitHub.
